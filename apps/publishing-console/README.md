# GUCC Publish Console

发布与复盘控制台。它位于 `apps/publishing-console/`，负责衔接现有的 GUCC WorkSpace、Cover Generator 和 `automation/创作中心`：

```text
WorkSpace 生成六平台发布包
  → Publish Console 拆字段、预检、执行登记
  → 各平台官方发布页上传并最终确认
  → Publish Console 保存数据快照并生成 AI 复盘包
```

当前版本包含一个本机发布助手：你点击一次“一键准备全部平台”后，它会在专用的已登录 Edge / Chrome 中逐个平台选择成片、尝试上传封面、填写发布字段，然后停在最终检查阶段。它不会点击最后的公开发布按钮。

## 打开方式

第一次使用先在仓库根目录安装依赖，需要 Node.js 20 或更高版本：

```powershell
cd C:\path\to\GUCC
npm install
```

之后直接双击：

```text
scripts/start-publishing-console.bat
```

它会在后台启动静态站点和本机助手，并打开：

```text
http://localhost:8000/apps/publishing-console/
```

页面右上角显示绿色“本机助手已连接”才可以执行一键上传。如果显示未连接，重新运行启动脚本，或在两个终端中分别运行：

```powershell
npm run publisher:assistant
python -m http.server 8000
```

也可以从 GUCC Portal 的 `Publish Console` 卡片进入，或者在 WorkSpace 的 `06 正式发布 / 发布包` 中点击“打开发布控制台”。

不要双击 `index.html` 使用。通过 `localhost:8000` 打开时，门禁、剪贴板、文件导入和 PWA 缓存行为更稳定。

### 首次登录设置

第一次启动后：

1. 确认右上角本机助手已经连接。
2. 点击“首次登录 / 检查账号”。
3. 工具会打开一个专用于发布的 Edge 或 Chrome 窗口。
4. 在这个窗口里依次登录 B站、抖音、小红书、视频号、YouTube 和 TikTok。
5. 登录完成后可以关闭页面，也可以直接回控制台开始发布。

登录状态保存在：

```text
%LOCALAPPDATA%\GUCC\publisher-profile
```

这是独立浏览器配置，不接管日常 Chrome / Edge 主配置。不要把该目录同步、上传或提交到 Git。

## 第一次使用：从 WorkSpace 到发布

### 1. 在 WorkSpace 准备发布包

1. 打开 `apps/video-workspace/`。
2. 在 `06 正式发布 / 发布包` 生成并整理六个平台发布包。
3. 点击 WorkSpace 的 `导出 WIP JSON` 或 `导出 DONE JSON`。
4. 确认 JSON 中已经有 `publishCN` 内容。

发布控制台目前识别以下固定平台标题：

- `## B站`
- `## 抖音`
- `## 小红书视频`
- `## 微信视频号`
- `## YouTube 简体中文`
- `## TikTok 简体中文`

这些标题正是 WorkSpace 当前“AI 完整平台包”Prompt 使用的格式。

### 2. 导入发布控制台

1. 打开 Publish Console。
2. 点击右上角“导入 WorkSpace JSON”。
3. 选择刚导出的 JSON。
4. 页面会自动填写项目标题、简称、游戏，并从 `publishCN` 拆出各平台最终标题、简介、正文、话题、Tags 和置顶评论。
5. 页面右下角会提示本次识别了多少个平台字段。

如果导入后某个字段为空，通常表示 WorkSpace 发布包的三级标题被改名、该平台内容尚未生成，或者 AI 没有按固定格式输出。可以直接在控制台补填，也可以回 WorkSpace 重新整理发布包。

### 3. 登记母版素材

在“项目与母版素材”中：

1. 点击“选择成片”，使用本机助手选择最终完整视频。
2. 点击“选择封面”，选择母版封面。
3. 填计划发布时间和时区。
4. 在公共备注记录版权、素材署名、AI 内容披露、合作关系等需要人工选择的事项。

本机绝对路径会保存在当前浏览器的控制台草稿中，并只发送给 `127.0.0.1:17877` 的本机助手。文件不会上传到 GUCC、GitHub 或其他中转服务器；助手直接把该文件交给各平台网页的文件输入框。

### 4. 检查平台独立字段

页面默认启用：

- B站
- 抖音
- 小红书视频
- 微信视频号
- YouTube
- TikTok

本期不发布的平台可以在“平台范围”关闭。每个平台都保存自己的字段，不使用“一个简介强行覆盖全部平台”的做法。

特别注意以下人工字段：

- B站：分区、原创/转载。
- 抖音：位置和内容披露。
- YouTube：可见性、是否面向儿童、视频语言和播放列表。
- TikTok：可见性、互动权限和内容披露。

### 5. 运行发布前检查

点击“保存并开始预检”。检查分两种：

- `错误`：缺少必填字段，或超过已确认的硬上限。存在错误时不能生成执行队列。
- `提醒`：超过 GUCC 使用的保守创作线、缺少素材、出现绝对化表达或疑似诱导互动表达。提醒不会阻止执行，需要你结合发布页核对。

国内平台的很多计数和权限会随账号、入口和平台更新变化。控制台不会把经验线冒充平台官方硬限制；各平台发布页的实时计数器和最终提示优先级最高。

### 6. 一键上传并填表

预检没有硬错误后，进入“逐平台执行”：

1. 点击“一键准备全部平台”。
2. 本机助手会复用专用浏览器的登录状态。
3. 它依次打开所有已启用平台，选择同一个完整成片并开始上传。
4. 它填写能够可靠定位的标题、简介、正文、话题、Tags、分区和选项，并尝试上传封面。
5. 控制台实时显示每个平台已处理的字段和需要注意的项目。
6. 全部结束后，各平台页面保持打开，状态变为“等待最终检查”。
7. 你只需要检查封面裁切、平台特殊选项、视频处理状态和最终文案，然后点击平台自己的发布或定时发布按钮。
8. 发布后回控制台登记作品链接和作品 ID。

平台网页会不定期修改 DOM。助手优先使用可访问名称、标签和占位符定位字段，而不是只依赖一个固定 CSS selector；如果某个平台改版导致字段没填上，控制台会明确显示“未自动定位字段”，不会假装成功，也不会误点最终发布。[Playwright 推荐的定位方式](https://playwright.dev/docs/locators)

Windows 下也可以运行：

```powershell
.\automation\创作中心\01-publishing.bat
```

它会一次打开六个平台发布页。网页控制台没有强行弹出六个标签，是因为浏览器通常会拦截批量弹窗。

作品 ID 虽然不是当前版本必填，但建议登记；未来接入官方数据 API 时，它是稳定取数的关键。

## 发布后复盘

### 录入快照

建议在以下时间点记录：

- `T+1 天`
- `T+3 天`
- `T+7 天`
- `T+30 天`

进入“数据复盘”，选择平台后点击“打开所选平台数据页”，把结构化指标填入表单。当前支持：

- 曝光量
- 播放量
- 平均观看时长
- 完播率
- 点赞、评论、分享、收藏
- 新增关注
- 观察备注

控制台自动计算：

```text
互动率 =（点赞 + 评论 + 分享 + 收藏）÷ 播放量
```

不同平台对播放、曝光和完播的定义不完全一致，所以原始指标会保留平台归属，不建议只按播放量跨平台排高低。

### 交给 AI 分析

保存快照后点击“复制 AI 复盘 Prompt”。复制内容包括：

- 项目信息
- 各平台发布状态、链接和作品 ID
- 所有真实数据快照
- 本地计算的互动率
- 防止 AI 编造数据的分析要求
- 下一期实验的输出要求

把它直接粘贴给常用 AI 即可。也可以下载 `.review.md`，回填到 WorkSpace 的 `08 进度记录 / 结项复盘`。

## 保存、备份和迁移

页面编辑内容会自动保存在当前浏览器：

```text
localStorage key: gucc_publish_console_v1
```

这只能防止误关页面，不是可靠归档。每次正式发布后建议点击右上角“导出控制台 JSON”。该文件包含平台字段、执行状态、作品链接和数据快照，可以在另一台电脑重新导入。

推荐文件流：

```text
项目简称.WIP.json          # WorkSpace 项目
项目简称.publish.json      # 发布控制台状态与快照
项目简称.publish.md        # 可读发布执行包
项目简称.review.md         # 可读复盘数据
```

## 当前边界

本机助手会自动上传和填表，但有意不做以下事情：

- 保存平台账号密码或 Cookie。
- 自动绕过验证码、风控和平台审核。
- 在无人确认时直接公开发布。
- 在 GitHub Pages 前端存储 OAuth secret。
- 点击平台最终“发布 / 提交 / 定时发布”按钮。
- 绕过验证码、扫码登录、风控和人工审核。
- 在封面编辑器尚未出现或视频仍在处理时强行操作封面。
- 自动读取所有平台的数据后台。
- 宣称风险词扫描等同于平台审核。

当前上传采用本机可见浏览器自动化，因此不需要把 Cookie、token 或 `client_secret` 写进仓库。长期最稳定的自动取数仍需要为各平台分别申请官方 API，并在 Supabase Edge Function 或其他私有服务端安全保存 OAuth token。

## 常见问题

### 为什么还要保留最后的发布点击？

因为各平台最后一步可能包含版权、商业合作、AI 内容、儿童内容、隐私、定时发布和审核确认。工具会把页面准备到可检查状态，但把不可逆的公开动作留给你，避免平台改版或账号差异造成误发布。

### 为什么页面里同时有普通文件选择和“本机助手选择”？

普通文件选择只能在网页当前会话里读取文件信息，浏览器不会暴露真实磁盘路径；一键上传必须使用“本机助手选择”得到本地路径。普通选择保留用于不启动助手时的手动预检。

### 能直接导入控制台自己的备份吗？

可以。“导入 WorkSpace JSON”按钮同时识别 `*.publish.json`。导入后会恢复平台字段、执行状态和数据快照。

### 平台改了字数限制怎么办？

平台规则集中在 `platform-rules.js`。修改对应平台字段的 `hardMax`、`safeMax`、`hardItems` 或 `safeItems`，然后运行项目测试。
