02 / 现在应该如何使用

  1. 从 GUCC 首页 进入。日常创作直接选择 创作中枢，不要从旧固定 Studio 或早期 Production 页面开始。
  2. 创作中枢有四个正式工作区：项目中枢（当前项目与六成果）、创作工作台（固定/灵活流程）、发布与复盘（发布草稿、人工确认、数据反馈）、规则与资料。
  3. 游戏数据用 数据库界面 维护；普通角色更新不用手工修改 SQL。
  4. 已完成或归档项目在档案与高级管理中查找。进行中的项目才应出现在首页主要操作区。
  5. 视频正式成果可以由你人工确认；不要把 AI 回答、已复制 Prompt 或文件路径当成成果已核验。发布动作必须最终由你确认。

参见 Creator OS v4 四工作区说明。既有七阶段固定 Prompt Studio、独立 Publishing Console 为兼容入口，并不代表主线必须再绕过它们。

04 / 正式代码修改和部署（实际 CI 门禁）

  1. 先确认：核对 main、生产结构、页面行为、当前任务；需要更改数据模型时先核对迁移。
  2. 分支与 PR：在独立分支实施修复，提交可审查的 diff；禁止跳过测试直接以历史安装 SQL 重装生产。
  3. CI：.github/workflows/ci.yml 使用 Node 22、npm ci、npm test 及真实 Chromium 隔离夹具的桌面/手机回归测试。
  4. 合并：CI 通过后合并 main。工作流自动构建 Pages 产物，并校验当前 HEAD 一致性。
  5. 部署：使用 GitHub Actions workflow-based Pages，不是旧文档中的“main / root 直接发布”。部署后以 release.json 的 SHA 与线上探针核验。
  6. 生产回读：确认实际网站、功能入口和主导航；涉及数据库更新时另外做独立只读回读。不要因为 PR merged 就直接宣称业务验收通过。

正式网址：https://inertia77.github.io/GUCC/。生产源代码版本以 GitHub main 与 Pages release.json 实际值为准。

05 / 本地维护与开发命令

在仓库根目录运行（Windows PowerShell）：

npm ci
npm test
python -m http.server 8000

然后访问 http://localhost:8000/。如需本机 Publishing Assistant，再单独执行 npm run publisher:assistant；本机 Creator Agent 使用 npm run creator:agent 并按对应工具说明传参。

数据库服务的本地跨域授权需要包含 http://localhost:8000。若使用其他本地域名或端口，先核实两个 Edge Function 的 ALLOWED_ORIGINS 配置，不能假设地址自动被信任。

06 / Supabase 变更边界

  • 前端只允许发布项目 URL 和公开的 anon/publishable key；service-role、JWT secret 和数据库密码不得写入前端、GitHub 或文档。
  • gameup-api 负责鉴权、app_users 活跃用户校验与已批准的 app_* RPC 映射；creator-project-api 承担 Creator 项目、文件位置、成果、渠道和发布类请求。
  • Schema / RPC 变更应进入 supabase/migrations/，必要时同时升级 Edge Function 和前端契约。不要直接复制过去的 02-install-command-center.sql、权限修复或去重脚本到已经运行的生产库。
  • 网页 Access Key 只提供静态站点的日常入口门禁，不等于数据库授权；真正的业务边界依赖 Supabase Auth、活跃白名单、后端验证和数据库权限。
  • 不应为了排错给 anon、authenticated 开放全表 CRUD，不应将 service_role 配置在浏览器。

07 / 快速排障

现象先核查建议操作
刚部署后仍是旧界面Pages release.json SHA、Service Worker 缓存确认部署成功；刷新页面、更新 PWA，不要盲目改数据库
页面能开但数据无法查询是否登录 Supabase、Auth token、app_users.is_active、Edge Function 响应先读日志与报错，不能直接扩权
本地出现 CORS 错误浏览器 Origin 与 Edge Function 的 allowlist只补充确需的可信来源，再按正式流程部署后端
项目数据不同步 / 冲突project/video 身份、revision、云端快照和本地草稿先保留两侧数据，按 UI 的冲突解决流程恢复，不强制覆盖
成果看起来已做完但状态未完成creator_deliverable_records 的人工确认及视频 ID核对当前视频，按正式成果状态操作，不绕过门禁
任务或游戏优先级不一致GUCC game_play_policies 与 TaskRing 数据所属项目分别核验，勿把 T1/T2/T3 写到 game_status
PR 测试通过但正式站不一致main HEAD、Pages deploy job、部署 SHA等待部署流程完成后核对线上 SHA；不以 PR 状态替代部署验证
