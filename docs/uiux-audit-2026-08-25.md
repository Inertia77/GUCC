# GUCC UI/UX 审核报告 — 2026-08-25

本轮目标：检查 GUCC 在手机端与电脑端的导航、首屏效率、表单密度、固定控件冲突、触摸操作、阅读体验与安全区适配，并直接修复高收益问题。

## 审核范围

- Portal
- GUCC DB / Command Center
- WorkSpace
- Cover Generator
- Publish Console
- AI Prompt Library
- Story Library
- Resource Library
- 全局导航 / PWA 壳层

审核方式：源码结构审计、响应式 CSS 规则审计、固定/粘性元素冲突检查、触摸目标与移动键盘场景检查、跨页面导航一致性检查。CI 用于防止代码层回归；真实设备视觉回归仍建议后续补自动截图测试。

## 结论

当前最大问题已经不是“页面完全不能用”，而是多个历史版本的样式叠加后，移动端容易出现信息过密、固定控件争夺屏幕、功能标签被压缩掉，以及不同页面导航行为不一致。桌面端主要问题则是功能页面首屏仍有少量展示性内容过重，以及历史布局规则对新全局导航存在耦合。

本轮优先修复影响日常操作频率最高、风险最低的项目。

## 全局导航审核

当前 5 个一级入口结构保持：

- 首页
- DB
- 创作
- 资料
- 更多

“创作 / 资料 / 更多”继续使用二级弹层，不把 9 个以上入口硬塞进底栏。该结构在手机端比横向滚动导航稳定，也避免重新回 Portal。

本轮没有再次大改桌面端右侧导航形态。原因是 WorkSpace 与 Cover Generator 自身已经有复杂编辑器布局，贸然把桌面全局导航改成另一种固定结构会扩大回归面。本轮先解决导航一致性、输入遮挡和功能可达性，下一轮如需重做桌面 Shell，建议配合截图回归测试一起进行。

## DB 手机交互的新逻辑

默认状态只显示：

1. 关键字
2. 筛选
3. 搜索
4. 新增

点击“筛选”后展开游戏 / 状态 / 清空 / 状态规则。按钮会显示有效筛选数量，例如 `筛选 · 2`。执行搜索后自动收起高级筛选，让结果立即回到视野。

这比把所有 Select 永久堆成纵向表单更符合手机端高频查询。

## Publish 手机流程的新逻辑

旧版小屏流程栏只显示：`01 02 03 04`。

现在保留语义：

- 01 准备发布单
- 02 发布前检查
- 03 逐平台执行
- 04 数据复盘

二级说明在手机端隐藏，既节省宽度，又不牺牲可理解性。

## 移动键盘规则

全局 Shell 会识别以下文本编辑状态：

- 普通文本 input
- textarea
- contenteditable

进入编辑时，手机端底部全局导航暂时退出屏幕；WorkSpace 的浮动工具层也同步隐藏。离开编辑后恢复。文件、复选框、滑杆、颜色选择器不会触发该规则。

## 仍建议后续继续做的项目

### 1. 自动视觉回归

当前 CI 主要验证代码和行为契约，尚未建立 360 / 390 / 768 / 1366 / 1440 宽度的截图基线。建议后续用 Playwright 建立至少以下页面的截图检查：

- Portal
- DB 角色页 + 编辑抽屉
- WorkSpace 工作区
- Cover Generator
- Publish Console
- Story Library

### 2. WorkSpace CSS 历史债务

WorkSpace 仍保留多个旧版本样式块，以及旧 6 项 Dock、左右侧栏、浮动操作栏的历史覆盖规则。当前新版 Shell 的后加载规则可以压住这些冲突，但维护成本偏高。

建议下一阶段单独做一次 WorkSpace CSS consolidation：把实际生效样式收口为一个主样式层，而不是继续叠 override。

### 3. Cover Generator CSS 历史债务

Cover Generator 同样存在多轮产品设计样式覆盖。当前实际表现可控，但未来继续改 UI 时容易发生 specificity 冲突。建议在功能稳定后整理。

## 本轮代码落点

- `assets/gucc-shell.js`：统一页面识别、viewport safe area、DB 移动筛选、移动键盘导航行为
- `assets/access-guard.js`：Portal 也启动全局 Shell
- `assets/gucc-uiux-v1.css`：跨页面 UI/UX 修复层
- `sw.js`：缓存版本升级，纳入新 UI/UX 样式

原则：高频工作入口优先、手机不堆满控件、固定 UI 不互相打架、语义不能为了省空间被删掉、低频说明退后但不消失。
