# Story Library｜来源与校对日志 v3.1

> 最后更新：2026-08-26  
> 本文件定义“什么资料能证明什么”。具体版本章仍必须保留自己的来源锚点。

## 1. 来源优先级

### S 级：游戏内已实装内容

优先级从高到低通常为：

1. 正式主线 / 开拓任务 / 潮汐任务 / 正篇；
2. 角色任务 / 番外 / 伴星任务 / 开拓续闻；
3. 游戏内档案、智库、物品、异象、阅读物；
4. 已实装过场、环境文本、可交互文本。

如果后续版本明确修正旧文本，以最新已实装内容为准，但必须保留“旧版角色当时为何会这样理解”的研究价值。

### A 级：官方公开资料

- 版本更新公告；
- 官方任务说明；
- 官网世界观 / 角色资料；
- 官方剧情PV、前瞻、版本专题页；
- 官方制作组通讯与研发通讯；
- 官方社媒补充设定。

官方宣传语可以证明“官方如何定位这一章”，但如果宣传文案和最终实装剧情细节冲突，事件事实以游戏内最终内容为准。

### B 级：完整实机 / 完整文本档案

- 无剪辑主线录像；
- 完整番外录像；
- 多语言文本录像；
- 能逐任务定位的社区 Wiki 文本页。

用途：确认任务顺序、具体对白、演出节点、人物是否真的在场。

### C 级：社区 Wiki / 攻略 / 剧情复盘 / 讨论

用途：
- 找关键词和遗漏章节；
- 找官方旧页入口；
- 对比不同解释；
- 发现值得回查的细节。

不可单独用于写死：
- 亲属关系；
- 真实身份；
- 死亡/复活状态；
- 测试服旧设；
- 时间机制；
- 幕后组织；
- “大家都这么猜”的理论。

## 2. 统一事实标签

- 【官】游戏内或官方直接确认。
- 【证】多个一手已实装信息能够稳定拼合。
- 【推】当前最合理，但仍可能被后续版本推翻。
- 【未】作品明确抛出、当前没有完整答案。
- 【可能未来】预知、演算、分支未来等“有信息价值但尚未发生”的内容。

### 反转规则

后续反转只改变解释，不删除旧事实。

例如：
- 达芙蒂尔后来证实卧底，不等于1.1损失没发生；
- 停云后来以忘归人回归，不等于1.3当时失踪悲伤是假的；
- 归寂介入姬子童年，不等于姬子之后所有选择都属于归寂。

## 3. 正式版本章的来源锚点标准

从 v3.1 起，新建或重点精修的正式版本章应尽量包含：

1. 至少1个官方 URL；
2. 游戏内正式任务/章节名；
3. 需要核对细节时，再加入完整无剪辑流程或文本页。

推荐写法：

```md
## 来源锚点

### 官方
- 版本更新：<URL>
- 任务说明：<URL>
- 游戏内任务：《任务名A》《任务名B》

### 完整流程 / 文本索引
- <URL>

### 二手资料用途
- 仅用于查任务顺序，不单独升级为【官】。
```

只写“官方公告 / Wiki / 完整录像”但不给具体锚点，属于**可读但可审计性不足**。

## 5. 时效性规则

所有“当前版本”“当前已实装”判断必须有校对日期，并同步写入：

- 游戏 README；
- 根 `00-index.md`；
- `CURRENT_STATUS.json`。

每次版本切换：

```text
确认官方已上线
→ 新版本写入事实层
→ 旧 current 改 historical
→ 更新 current_version / verified_at / review_by
→ 自动检查
```

CI不能代替联网，但可以发现我们自己声明的 `review_by` 已经过期，防止资料库长期沉默过期。

## 6. 社区信息的正确工作流

```text
社区看到线索
→ 找任务名 / 人名 / 关键词
→ 回查游戏内、官方页或完整流程
→ 判断【官/证/推/未】
→ 写入正文
```

禁止：

```text
高赞评论 / 剪辑标题 / 二手总结
→ 直接写成官方真相
```

尤其不要因为标题“炸裂”“实锤”“终于揭晓”就自动提升证据等级。
